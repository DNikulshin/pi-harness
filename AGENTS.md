# AGENTS.md — pi-harness

Адаптер Pi для ядра `@dnikulshin/harness`: переносит в код то, что раньше держалось на дисциплине
модели — регистрацию команды `/cycle`, чтение `cycle-driver next`, запуск гейтов, показ состояния и
артефактов, подтверждения владельца на переходах.

Ядро — внешний пакет. Здесь нет ни одной его внутренней строки: ни `scripts/**`, ни
`scripts/lib/**`.

## Границы

| Что                    | Как                                                                                                              |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Обращение к ядру       | только `bin`-команды (`harness-cycle-*`, `harness-*`) и файлы `.pi/` (`.pi/harness.version`, `.pi/artifacts/**`) |
| Импорт ядра            | запрещён; проверяется `test/imports.test.mjs`                                                                    |
| Совместимость          | `peerDependencies["@dnikulshin/harness"]`; несовпадение — отказ с обоими номерами, код 1                         |
| Правки протокола цикла | только в ядре (`DNikulshin/dev-harness`), здесь — потребление контракта                                          |
| Управление стадиями    | за CLI ядра; адаптер показывает и подтверждает, но не подменяет `cycle-state`                                    |

## Команды

| Команда             | Что делает                                   |
| ------------------- | -------------------------------------------- |
| `npm test`          | `node --test`: тесты модулей и контракта CLI |
| `npm run typecheck` | `tsc --noEmit`: строгая проверка JS + JSDoc  |
| `npm run format`    | prettier                                     |
| `npm run check`     | тесты + `tsc` + проверка форматирования      |

CI (`.github/workflows/ci.yml`) гоняет `npm run check` и проверку совместимости с опубликованным
ядром из реестра.

## Правила

1. **Стиль — JS + JSDoc, строгий `tsc`.** Типы не «для галочки»: `checkJs` включён, `strict`,
   `noUncheckedIndexedAccess`.
2. **Новая зависимость — только с обоснованием.** Сейчас runtime-зависимостей нет: разбор версий
   (`src/compat.mjs`) написан свой, потому что диапазон объявляем мы сами.
3. **Никаких импортов ядра и его путей.** Если чего-то не хватает — это дефект контракта ядра,
   заводится issue в `DNikulshin/dev-harness`, а не обходится чтением внутренностей.
4. **Отказ лучше догадки.** Неизвестный диапазон, битый `.pi/harness.version`, нечитаемая версия —
   внятная ошибка, а не «наверное, совместимо».
5. **Секреты не печатаем.** Диагностика не содержит содержимого `.env*` и тел артефактов.
6. **Работа по issue.** Ветки `feat/*`, `fix/*`, `chore/*`, `docs/*` от `main`, имя содержит номер
   issue; коммит и push — только в рабочую ветку задачи, `main` защищён.

## Связь с ядром

Контракт, который адаптер потребляет: `docs/release.md` (публичный API, версии) и Приложение A
`docs/orchestrator-core.md` (схемы артефактов) в репозитории ядра. Порядок правок — «сначала ядро,
потом адаптер»: релиз ядра с изменением контракта, затем PR здесь.
