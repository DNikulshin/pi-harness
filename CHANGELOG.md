## [0.1.1] — 2026-11-21

Первая **опубликованная** версия. Тег `v0.1.0` существует, но ничего не опубликовал: шаг
«Собрать архив» падал с `ENOENT` — `npm pack --pack-destination dist` не создаёт каталог `dist/`,
а он в чистом checkout отсутствует (локально я его создал руками и потому не увидел). Тег не
перезаписывается (ruleset `release-tags`), поэтому исправление вышло следующей версией.

### Fixed

- `release.yml`: `mkdir -p dist` перед `npm pack`; тест на workflow проверяет порядок шагов и путь
  публикации с `./`, чтобы это не повторилось.

## [0.1.0] — 2026-11-21

Первая версия в npm: адаптер ставится как пакет Pi и ведёт цикл на опубликованном ядре
`@dnikulshin/harness ^0.2.0`.

### Added

- Сквозной тест на ядре **из реестра** (`npm run test:e2e`, выключен по умолчанию): установка
  настоящего пакета, `harness-init`, `cycle-state init` в git-фикстуре, живой `cycle-driver next`
  по контракту и `run` до первой остановки (`spawn`), плюс негативные сценарии — версия вне
  диапазона (код 1, оба номера) и расхождение версии ядра с `.pi/harness.version` (предупреждение).
- `nightly-e2e.yml`: тот же прогон на `@latest` по расписанию — дрейф контракта ядра виден до
  релиза адаптера, а не по жалобе потребителя.
- `/cycle next`: текущий шаг из `cycle-driver next` — стадия, действие, цель, причина, ожидание,
  последние завершённые этапы и готовая команда. Ответ сверяется с контрактом
  `cycle-driver.next/1`: чужая версия формы — отказ, а не догадка.
- `/cycle run`: исполнение детерминированных шагов по одному через `cycle-driver run
  --max-steps 1`, с остановками на `spawn`/`handoff`/`stop`/`blocked` и подтверждением владельца
  перед переходом в `PR`/`ESCALATED`. Отказ не двигает стадию; упавшая команда показывается с
  названием и кодом.
- `src/driver.mjs` и `src/run.mjs` в публичных `exports` (`./driver`, `./run`): запуск `bin`
  ядра и прогон шагов доступны программно, без TUI.
- Команда `/cycle`: находит корень проекта, читает установленную версию ядра и версию шаблонов,
  сверяет их с `peerDependencies` и сообщает состояние. Несовместимая версия останавливает цикл до
  начала работы.
- `pi-harness-check`: та же проверка из командной строки — код `0` при совместимости, `1` при
  отсутствующем ядре или версии вне диапазона.
- Граница с ядром проверяется тестом по импортам (`test/imports.test.mjs`): ни `scripts/**`, ни
  `scripts/lib/**`.
