# Политика безопасности

Адаптер запускает `bin` ядра `@dnikulshin/harness` и читает артефакты цикла в `.pi/artifacts/`. Он
не импортирует ядро и ничего не пишет в артефакты — на этих двух обещаниях держится безопасность
адаптера, и обход любого из них считается уязвимостью.

## Поддерживаемые версии

| Версия                              | Поддержка                                   |
| ----------------------------------- | ------------------------------------------- |
| `0.2.x`                             | да — исправления выходят патч-релизом       |
| `0.1.x`                             | нет — обновитесь до `0.2.x`                 |
| git-ссылки, форки, локальные сборки | нет: только пакет из npm и теги репозитория |

Совместимость с ядром объявлена в `peerDependencies` (`@dnikulshin/harness ^0.2.0`): версия вне
диапазона — отказ с кодом 1 до первого шага цикла.

## Как сообщить об уязвимости

**Только приватно**:
[приватное сообщение GitHub](https://github.com/DNikulshin/pi-harness/security/advisories/new)
(Security → Advisories → Report a vulnerability). Публичный issue или PR с деталями вредит раньше,
чем выйдет исправление.

Полезно указать:

- версию адаптера (`npm ls @dnikulshin/pi-harness`), версию ядра
  (`node -p "require('@dnikulshin/harness/package.json').version"`), версию Pi и Node, ОС;
- шаги воспроизведения и минимальный набор файлов (`.pi/harness.config.json` можно урезать);
- какое обещание нарушено и каков эффект.

**Секретов в отчёт не присылайте.** Если уязвимость про утечку — достаточно места утечки; значения
замените на вымышленные.

## Что считается уязвимостью

1. **Обход проверки совместимости.** Возможность начать цикл, когда версия ядра вне
   `peerDependencies`, или когда `peerDependencies` подменён содержимым пакета.
2. **Принятие чужого контракта.** Шаг считается исполненным по ответу не формы `cycle-driver.next/1`
   (адаптер обязан отказать, а не угадывать).
3. **Выход за пределы каталога цикла.** Путь из ответа драйвера (`cycle.dir`), из `gates.<n>.json`
   (`log`) или аргумента `/cycle evidence` читает файл вне каталога цикла и вне `evidence/`.
4. **Запись в артефакты.** Любая запись адаптера в `.pi/artifacts/**` — нарушение границы «стадиями
   управляет CLI ядра»: подмена `state.json` или `decision.<n>.json` меняет решение цикла.
5. **Утечка содержимого.** Тела артефактов, фрагменты логов или `.pi/harness.version` попадают в
   вывод, который уходит наружу (телеметрия, отчёты, публичный текст).
6. **Supply chain.** Возможность опубликовать или подменить архив так, что потребитель получит код,
   не прошедший проверку состава (`tooling/check-package.mjs`) и `--provenance`; отсутствие бита
   исполнения у `bin` относится сюда же.

## Что уязвимостью не считается

- **Адаптер запускает `bin` ядра.** Это доверенный код проекта, установленный потребителем, — та же
  модель доверия, что у гейтов ядра (см. README ядра, раздел «Гейты — это код, который вы
  запускаете»).
- **Гейты проекта выполняют свои команды** с правами пользователя — поверхность проекта, не
  адаптера.
- **Содержимое артефактов принадлежит проекту**: если в `evidence/` попал секрет, причина — в ядре
  или в проекте, и сообщать нужно туда (см. ниже).
- **Ложные срабатывания** проверок — дефект качества, не безопасности: обычный issue с `type:bug`.

## Чего ждать

- подтверждение получения — в течение 7 дней;
- оценка и решение — в приватном треде; исправление выходит патч-релизом (версия в npm неизменяема,
  поэтому всегда новая версия);
- публикация GitHub Security Advisory — после выхода исправления, с вашим кредитом по согласию.
